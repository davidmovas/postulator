Windows-only Wails v3 desktop app. Go 1.27, CGO off, local SQLite, no server.

## Hard rules (do not violate)

1. **No comments in Go, TypeScript, YAML or PHP** — not inline, not godoc, not package docs. Naming carries meaning; prose lives in `docs/` and here.
2. **No stubs, no TODOs, no placeholders.** If something cannot be done, stop and say so. A hole that looks finished is worse than an unfinished task.
3. **Interfaces are declared by the consumer**, never by the implementation and never in advance.
4. **TDD.** Failing test first, run it, implement, run it, commit. Table tests. Gates: `domain`+`application` ≥ 80%, module ≥ 70%, kernel ≥ 90%.
5. **Cursor pagination only.** No offset, anywhere.
6. **JSON is camelCase**, timestamps are RFC3339 UTC, ids are UUID v4 text.
7. **Errors crossing a boundary are `*kernel/errors.Error`** with a frozen code. Adapters convert driver and transport errors at their own edge.
8. **Secrets never reach a log, an artifact or a plain column.**
9. **No new `.md` files** beyond `CLAUDE.md` and the set in section 10 of the spec.
10. **Bad code is rewritten, not patched.** Commit your own work on `dev` with conventional commits; never amend, rebase, force-push or `--no-verify`. `master` takes a PR from `dev` only when the owner asks.

## Layout and workflow

`cmd/postulator` (bootstrap) · `internal/kernel` (shared) · `internal/domain` (pure) · `internal/application` (use cases) · `internal/adapters` · `internal/runtime` (run engine) · `internal/transport` (wails, agent) · `internal/app` (composition root) · `frontend` (Vite stub) · `wp-plugin` (PHP).

Dependency rule, enforced by `internal/app/deps_test.go`: domain sees only kernel and stdlib, application sees domain and kernel, only `app` imports `transport`, only `kernel/paging` imports squirrel, and `transport/agent` never reaches `adapters/llm/openai`. The composition root builds by area in `internal/app/build_*.go`.

```
task build                 bin/postulator.exe, builds the frontend and bindings first
task package               the NSIS installer; task e2e:full the whole loop on docker
go test -race ./...        golangci-lint run from $(go env GOPATH)/bin
go run ./cmd/covergate     needs coverage.out from -coverprofile
```

## Footguns

- **A kernel rule**: `log.Logger.Close()` does not call `Sync()`, because syncing a pipe fails on Windows and lumberjack writes unbuffered, so closing the sinks is the whole job. An agent turn recovers its own panic and ends `INTERNAL`; there is no timeout middleware any more.
- **Rules that look like bugs and are not**: a cursor records the sort it was issued for and refuses another `ORDER BY`; `kernel/dto` keeps its own limit constants rather than importing `kernel/paging`, which would drag squirrel into every DTO; a step a run kind owns (`sync_site`, `relink_page`, `revert`) is a `PerKindStepName` and never a `StepName`, which is what keeps it out of `vocab.ts`, the blank template's recipe and three tool enums at once; `ModelsService.SpendReport` takes no cursor, being an aggregate.
- **Never compare entity names or anchors with `strings.ToLower` or `EqualFold`**: use `graph.Key`, or Go merges or refuses what the store accepts (Café and CAFÉ are two entities; `TestTheGraphKeyRefusesWhatTheStoreRefuses` proves the rule against a real insert). A keyword is found by `keyword.List.Find`, and a list of texts is deduplicated by `graph.Distinct`.
- **Live events are dropped, not buffered** — a progress UI replays `RunsService.ListEvents` — and `frontend/src/generated/events.ts` and `vocab.ts` are generated, committed and checked by a test, while `frontend/bindings/` is generated, gitignored and regenerated only by `task build`, so `npm run typecheck` alone cannot see a bound field a Go change removed: run `task build` before a tag. Those generated files and `go.mod` are pinned to LF, and `frontend/dist/.gitkeep` is committed on purpose because `frontend/assets.go` embeds `all:dist`, so Vite runs with `emptyOutDir: false` and unhashed names or a fresh clone stops building.
- **`TestTheToolSchemasFitTheirCeiling` is a deliberate tripwire**: every tool schema is resent on every round of every turn, so a new tool raises `schemaCeilingBytes` (61,440 for 61,437 bytes after stage 2a) in the same commit and a change that shrinks the schemas lowers it again. A request struct a tool takes is part of that schema: its `description` tags say what a field takes, its default, its limits and the tool an id comes from, and nothing every field would repeat.
- **OpenAI's Responses API, as the live probe found it**: a structured answer is a strict `json_schema` (every object closed, every property required, an optional one nullable); `minimal` effort, `temperature` at a reasoning effort and `max_output_tokens` under 16 are refused, and the server's default effort is medium even on luna, so an effort is always sent; a `function_call` needs its output in the same input; a reasoning item without its encrypted content is a 404 under `store: false`, so none is kept; an error can arrive inside a stream that answered 200, with no `[DONE]`; a key with no credit validates the request before it refuses, which is how a shape is proven for free. `openaitest` never imports `openai`, as `wptest` never imports `wp`. The chain is tuning → retry → limiter → ledger → recordreplay → openai, so a retried attempt is its own ledger row.
- **PowerShell splits `-coverprofile=coverage.out` into two arguments**, which is why every go and task step of the CI Windows job runs under `shell: bash`.
- **`runs.kind` carries a `CHECK` rebuilt by migration 0025** to accept `repair` and `revert`; a ninth kind needs the same rebuild (`NO TRANSACTION`, foreign keys off, explicit `BEGIN`/`COMMIT`) or the insert fails.
- **golangci-lint must be built by the Go release the module targets** and run from `GOPATH/bin`; it runs `errcheck` with `check-blank`, `govet` `enable-all` with non-strict `shadow`, `fieldalignment` off because field order is the JSON order, `gocritic` without `hugeParam`, `misspell` US English ignoring `cancelled`.
- **A product is written in two places, in this order**: the short description, the attributes and the image through `wc/v3` first, then the description through the plugin's raw route against a hash read after that save, because WooCommerce saves the whole post again when a post field changes and kses runs over `post_content` once more. `wc/v3` replaces the whole attribute list, so every attribute the product carries is sent back; the name, price, stock, SKU, status, slug and categories are never sent. A product row keeps the sheet's URL in `planned_path`, which a second import and the export read, and takes no parent from its path.
- **A migration that shipped is undone by a later one, never edited**: the flag model's 0033 and 0034 are undone by 0042 and 0043, and the category records' 0039–0041 by 0044, whose down brings them back.
- **Docker and WordPress quirks**: the WP-CLI image's `www-data` is uid 82 and the WordPress image's is uid 33, so the compose `bootstrap` service runs as `33:33`, needs the `WORDPRESS_DB_*` variables and `WP_ENVIRONMENT_TYPE=local` for application passwords over HTTP; `modified_gmt` has no timezone suffix and core REST filters `modified_after` on the site-local column, which is why the plugin's `/content?since=` exists; `"meta"` arrives as `[]`, not `{}`, for a post type with no registered meta, and `wp.metaBag` takes the array, the object and null.
- **Three docker projects from one compose file**: `task e2e:* STAND=vanilla` is the suites' block-theme stand on 8088 (project `postulator-test-vanilla`, the compose default), `STAND=replica` the replica of the client's first site on 8087 (project `postulator-test-replica`), and `task sandbox:*` the owner's WordPress on 8089 (project `postulator-e2e`), which comes up bare like a client's site unless `E2E_PLUGIN=1`, is provisioned as a stand only by `task sandbox:provision STAND=` and is wiped only by `sandbox:reset` (Windows reserves 8091–8190 here). A stand's bootstrap writes `docker/e2e/.env.<stand>`, which the suites read through `E2E_STAND` or `POSTULATOR_E2E_ENV`; they force-delete whole sections of the site they run on, so both harnesses refuse 8089 and the sandbox's project, and a stand's term ids start at 100000 because the term-id refusals presume no post shares the id. The plugin is installed from `bin/postulator-companion.zip` (`task plugin:deploy STAND=` reinstalls it) and the replica's mu-plugin is copied, never bind-mounted, because wp-admin's Delete removed the repository's sources through the mount; the replica's theme, plugin and class names live under `docker/e2e/stands/replica` and nowhere in Go or PHP.
- **The companion plugin's post routes answer a content post only** (a public post type other than an attachment), because WordPress numbers a variation, a reusable block, a navigation menu and a template like a page and the raw PUT once wrote into a navigation post. A preview's noindex needs Rank Math's and Yoast's own robots filters, since both replace core's `wp_robots`. `/rendered` filters inside a one-post main query, or a snippet guarded by `is_singular` or `in_the_loop` injects nothing in a REST request. `/content` defaults to the four types a released app asks for. A new capability joins `wp.requiredCapabilities`, the fake's defaults, the PHP `CAPABILITIES`, `openapi.yaml` and three pinned test lists in the same commit. `wpCLI` in the e2e harness costs about six seconds a call.
- **`go test -tags e2e` is the only thing that compiles `internal/e2e` and `internal/adapters/wp/e2e`**, `task lint:e2e` is not optional (it refuses to start beside another golangci-lint; run it alone or by hand with `--allow-parallel-runners`) and `gofmt -l .` is what catches formatting there; `wptest` must never import `wp`, because the fake is a second, independent implementation of the same contract.
- **`VACUUM INTO` cannot write through the adiantum VFS** — it opens the target with no key — so snapshots and restores go through the SQLite online backup API with a plain `file:` URI.
- **A template placeholder is expanded in `templates.ResolveForPage` and nowhere else**; `template.Validate` refuses any `{…}` outside `template.Placeholders()`, so a heading the validator compares is never the placeholder itself. The writer answers a `content.DraftAnswer` with a slot per section and `content.Assemble` puts the brief's headings on; do not compare a body with the raw spec.
- **`run_items.blocked_by` has no foreign key on purpose** — SQLite's `DROP COLUMN` refuses a constrained column, so the down migration would not round-trip — and the release predicate lives twice by design, in `selectRunnableItems` and `selectItemsAwaitingParent`: the blocker's page when there is a blocker, else `pages.parent_page_id`. Change one and the other.
- **A step that returns `TransitionWait` with no artifact and no checkpoint is recorded `ExecStarted`**, never `ExecDone`, or `reuse()` skips it when the item wakes. A step that returns `TransitionPause` keeps its artifacts and is recorded `ExecFailed` with the note, and `sc.Accepted()` is how it learns a person accepted its findings.
- **`Engine.EstimateRun` takes the run and the templates a start is about to assign** (`nil` for none) and resolves each target's template itself; `runtime.Deps.Keys`, `runtime.Deps.Tuning` and `steps.Deps.ImageModel` are required, not optional, and every harness that builds an engine passes a key store and a tuning policy. The writer's ceiling is `writerCeiling(spec, wpType, attempts)`, doubled once (`ceilingDoublings`), and the adapter adds the effort's reasoning allowance and clamps it; `tokensPerWord` in `runtime/budget.go` (2.2) is the estimate's and `steps.tokensPerWord` (3) the ceiling's, on purpose.
- **The observation (`application/observe`, driven by `sync_site`) is incremental**: the first walk, one with `full`, every Nth (`settings.observe.fullWalkEvery`, 10) and every walk without the plugin cover the whole site; the others pass the plugin a `since` taken from the site's own stamps (the newest `modified` the previous walk saw, minus that walk's duration and a second, so a server clock behind ours misses nothing), and a page's render is fetched again only when its `modified_gmt` or its body moved past the render's `extracted_at`, or on `renderRescan`. So a page deleted on the site is archived on the next **full** walk only, a render that could not be fetched is `render_unreachable` and is tried again every walk, and `page_identity.observed_at` against the walk's start is how "seen this walk" is known: the checkpoint carries no page ids. A denied field (price, SKU, stock, attributes, a variation's facts) is always agreed (`Fields.Agree`), only a writable field raises `field_changed_on_site`, an open finding re-raised with the same subject touches nothing, and a re-pulled item nothing changed on writes nothing (a field moves only when its hash moves, the page row only when something but its stamps moved).
- **Two hashes, never mixed**: `block.BodyHash` is the exact sha256 of the bytes, equal to `wp.ContentHash` and the plugin's `content_hash`, and it is the hash of every body snapshot (`page_bodies.hash`, `Record`, `Observe`, a core or store item's `ContentHash`); `block.Hash` folds CRLF and trims and is a block's identity in `page_blocks_written` only. Hashing a body with the folded one made our own write read as `body_changed_on_site` on every CRLF body and every product without a description.
- **The observation reads the site before its unit of work and writes inside it**: a reader called inside `inUnit` holds the one SQLite writer for a whole round trip, and the observe fakes count such reads (`TestTheObservationReadsTheSiteOutsideItsWriteUnit`). The render stage never visits an archived page or one the walk is about to archive, a failed `GetRendered` is `render_unreachable` like a failed visit, and that finding's subject is the page's path and the status only, so a dismissed one is not reopened by a nonce or an error text.
- **`application/observe` cannot import `adapters/wp`**, so it declares its readers over its own item types and `runtime/steps/observe_readers.go` adapts `*wp.Client`; a change to a `wp` type reaches the observation through that one file. `render.Extract` takes the page's path as `Document` and every href resolves through `Site.ResolveAt`; `Site.Resolve(href)` is `ResolveAt(base, href)`.
- **A parent at the site root is never a WordPress parent on a creation** (`steps.parentOf`, `runs.parentOf`), though `DeriveParent` may name the front page as a flat page's parent by `url` for the tree; a crumb at `/` is dropped like the front page, or vanilla's "Home" crumb would be unresolved on every term page. `publish` sends title, content and status on an update and checks slug, address and parent only on the creation it made, the retry included (`writeRequest.created`).
- **A crumb resolves by its link, then by the redirect the render stage looked up, then by its exact name only when it has no link or a dead one** (`pagemap.DeriveParent`; the method is `pages.parent_method` beside the reason). The lookups (`wp.Client.Resolve`, anonymous HEAD) run in the render stage and live on the crumb in `page_renders.trail`; `derive` stays offline and writes only `PageRepo.UpdateDerived` and `SiteRepo.UpdateObservation`, never a whole row, or an edit made during a walk is lost. A Home-only trail is weak (the other trails, then the WordPress parent, first); the front page is the root, never technical; a page whose own visit lands elsewhere keeps nothing of that page's render; a live link the model lacks never falls to its name.
- **Writers that share one tree commit with `git commit -- <paths>`** and stage nothing ahead of their commit; a plain `git commit` takes the whole index, and R's render commit swept another writer's staged deletions in on 2026-10-18.

## Standing rulings

Dated in full in [`docs/DECISIONS.md`](docs/DECISIONS.md); these are the ones that change how you write code here.

- **2026-09-17** — UUIDs come from the Go 1.27 standard library; `kernel/id.Valid` does its own canonical v4 check. `paging.Cut` is a `Keyset` method. `errors.Wrap` returns `error`, never `*Error`. The kernel exports nothing whose only caller is its own test.
- **2026-09-17 (phase 1B)** — A service method returns `wails.Convert(err)`, never the raw error; the error marshaller is set per service with `NewServiceWithOptions`; `application.RegisterEvent` is not used, the Go registry renders the typings.
- **2026-09-18 (phase 3)** — `adapters/wp` is the one place page numbers are legal; `wp.ContentHash` is `hex(sha256(raw))` and frozen; `wp-plugin/openapi.yaml` is the contract neither side changes alone; the plugin never removes a kses filter and passes `wp_slash` on every write.
- **2026-09-18 (phases 9-10)** — `robfig/cron/v3` and `x/net/html` are the only third-party packages the domain may import; a tool call's arguments are masked before they reach a ledger, an event, a summary or a stored history.
- **2026-09-18 (phase 11)** — A Wails service declares the use-case interface it consumes and `Services` takes a `wails.Deps` from the composition root; `SettingsService` is the only surface that accepts a credential.
- **2026-09-18 (phase 12)** — A Wails service resolves its use case per call through a `Source[T]`, which answers `Locked` while the core carries no composition; `app.Open` starts locked when `master.key.pw` exists; `app.Config.Provider` is the seam an end-to-end harness uses to compose the real application over `adapters/llm/fake`.
- **2026-09-22/23 (hardening)** — A run kind that owns its steps hands them out and no template overrides them; a revert is a run, and every write to the site keeps what it replaced beside it in the artifact the step already produces; one `pagemap.Site` answers where an href points and `content.Subject` says which page is "self"; a tool takes its own argument structs, never the window's DTOs.
- **2026-09-24 (2.2.0)** — An import never plans `/`; a draft is assembled from the brief and a missing required section is tried again, never failed; the linker owes phrases and writes a plain one itself before it gives up; validation grades and a person accepts, through `Engine.Accept`; a child is queued behind its parent through `blocked_by`; the estimate prices each page on its own template and refuses a run its preflight blocks; every step event carries the step's sentence.

- **2026-09-25** — An owed link is placed or said, never dropped: the brief and `repair_links` owe every target within the budget, a neighbor that owes a new page a link gets a plain sentence when it has no anchor, and what a finished page lacks is its `note`. A template picked at the start is assigned to the chosen pages. A page is on the site when it has a WordPress id, and the link audit gives every owed link a state. An untouched built-in is refreshed from `seed/superseded`, an edited one never.
- **2026-10-02** — Keywords are one `keyword.List` sorted by volume and read once through `pagemap.Keywords` (the page's, else its entity's); a keyword cell is parsed only by `keyword.Parse`. An entity's name is unique under its parent (`scope_entity_id`), every parent-edge change settles the scopes, and a shared name reaches a prompt or an anchor only through `graph.Labels`. An import gives every row with a page an entity, matches by parent and name, refuses an ambiguous one, and never places a group's page by position. An entity no page carries is passed through by the link plan as `no_page`.

- **2026-10-03** — The client creates products in WooCommerce and Postulator edits them where they stand, never writing what the store owns; since 2026-10-17 what the store owns is the hard-deny list and what a product run writes is the product type's field scope. A product run is live-only and refused before anything is spent without an editable store, the plugin or a product. A row finds its product by its address, its slug, then a name only one product carries (since 2026-10-17 every row finds its page by URL, slug, entity name, title or H1, then SKU), keeps the sheet's URL as `planned_path`, and a product synced later claims the row that waited for it.
- **2026-10-03 (models)** — OpenAI only, through our own Responses client in `adapters/llm/openai`; nothing names another provider, a new profile or model of one is refused, and a stored one is passed over when a role resolves, never an error. A structured answer is one strict call with no repair round. Effort and service tier belong to a role, set in `llm.effort.*` and `llm.tier.*` and filled by the outermost `tuning` decorator; never on a catalog row. Every attempt is a ledger row, and a call's purpose is derived through `llm.PurposeRules`, never stored. A built-in model's price is never 0: an override's zero takes the built-in price. A single call is sent outside the prompt cache; only a recurring prefix family names a cache key.
- **2026-10-04** — No WordPress or WooCommerce category is written, and none is a record of its own; since 2026-10-17 a page's taxonomy terms are read as facts of its identity and its hierarchy, and a product category stays a page that is read, never written. A sheet's Category columns are the client's WooCommerce categories, which he keeps himself: only a Root Entity or Root header makes entity groups, any other level column is ignored, and a URL parent wins inside the row's Root group. A workbook is one preview and one apply in the workbook's order, and every finding names its sheet.
- **2026-10-12** — The companion plugin targets PHP 7.4, the client's host: nothing newer than 7.4 in `wp-plugin`, no `match`, `?->`, named arguments, union types or `str_contains`, and `task plugin:lint` runs on 7.4. Its version moves with its contract since 2026-10-17; 1.2.0 is the last release under the old name.
- **2026-10-17 (the site model, stage 0)** — Every page of a site, of any post type, is one structured object: identity, fields, a body of addressable blocks, the regions of its render, typed links, its JSON-LD, a page type and a derived hierarchy with a reason per value; four providers (core REST, WooCommerce REST, the companion plugin, the public render) fill it behind a field registry, and the writer, the agent and the UI see the model, never a provider. The raw `post_content` is editable and what the render adds is read and never written; the content root is found by locating the content's text in the render, never by a selector, and no theme name, CSS class or site path lives in Go or PHP. The raw body and the field values are stored locally, current and base, never the rendered HTML. The body is edited as blocks under the raw route's hash, untouched blocks keep their bytes, and nothing we write marks the client's content. Slug, prices, stock, SKU, status, every taxonomy, the WordPress parent and a variation's attributes are never written to an existing page; the parent is read from a BreadcrumbList, then an ARIA breadcrumb, then the WordPress parent, then the URL. Page types are the client's names over presets and replace the entity `kind`. A discrepancy between site, workbook and model is a finding a person or the agent resolves, never a silent merge. Nothing a visitor receives names the program (public HTML, the content we write, media names, titles, alts and captions, whatever the plugin emits on the front end, our User-Agent), and a test proves it; the plugin itself keeps its name, `postulator/v1` and its protected `_postulator_*` keys (the owner's answers, same date). A planned page's one creation call may set status, parent and slug; an outdated plugin is named by its manifest's version and capabilities; the User-Agent is neutral with a per-site override; the sandbox on 8089 is provisioned only on explicit command.

- **2026-10-18 (stage 1b)** — A site is observed into the model by `sync_site` in five stages, incrementally through `since` with a full walk every Nth; a relative href resolves against the document on every side (plugin 1.4.1, `Site.ResolveAt`); a breadcrumb nav is an `aria-label` or a microdata `BreadcrumbList`, with or without a list; `noindex` is read from the render's robots meta; the store's facts are denied fields whose base follows their current; a planned page keeps the workbook's parent under the reason `workbook`; the derived parent wins over a workbook parent and `parent_differs` says so; the `repair` kind is retired from the start, the tools and the drawer; the site root is never a WordPress parent on a creation.

- **2026-10-18 (stage 1c)** — A crumb resolves by link, redirect or name as above; a dead link falls to its name and a redirect's landing must carry it; a parent loop is broken at its first on-site path with `parent_cycle`; `archive` is a root state and `not_found` names only text the render does not hold; self links are no page links, a `rel` tag, category or author link is navigation, the listing rule (three product links, two products) holds everywhere; an owed link, an orphan and an off-graph link count contextual links only, and technical, term and front pages are never orphans; the page model is bound on `PagesService` (`Model`, `ModelSummary`).

## Product guardrail

Postulator builds one structured model of a client's site (its pages, fields, hierarchy, products and links, reconciled with his workbooks and his entity graph) and edits the site's content through it, so every page is written with the full picture and linked as the graph says. Reject features that do not serve that loop.
