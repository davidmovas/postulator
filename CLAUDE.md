# CLAUDE.md — Postulator v2 (session contract)

Read [`docs/STATUS.md`](docs/STATUS.md) first; it says what landed and what is next, and [`docs/DECISIONS.md`](docs/DECISIONS.md) says why. Then [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md), [`docs/CONVENTIONS.md`](docs/CONVENTIONS.md), [`docs/CONTRACTS.md`](docs/CONTRACTS.md), [`docs/ORCHESTRATION.md`](docs/ORCHESTRATION.md), [`docs/VISION.md`](docs/VISION.md). The binding design is [`docs/superpowers/specs/2026-09-17-postulator-v2-design.md`](docs/superpowers/specs/2026-09-17-postulator-v2-design.md); the phase list is [`docs/superpowers/plans/2026-09-17-postulator-v2-roadmap.md`](docs/superpowers/plans/2026-09-17-postulator-v2-roadmap.md).

Windows-only Wails v3 desktop app. Go 1.27, CGO off, local SQLite, no server.

## Hard rules (do not violate)

1. **No comments in Go, TypeScript, YAML or PHP** — not inline, not godoc, not package docs. Naming carries meaning; prose lives in `docs/` and here.
2. **No stubs, no TODOs, no placeholders.** If something cannot be done, stop and say so. A hole that looks finished is worse than an unfinished task.
3. **Interfaces are declared by the consumer**, never by the implementation and never in advance.
4. **TDD.** Failing test first, run it, implement, run it, commit. Table tests. Gates: `domain`+`application` ≥ 80%, module ≥ 70%, kernel ≥ 90%.
5. **Cursor pagination only.** No offset, anywhere.
6. **JSON is camelCase**, timestamps are RFC3339 UTC, ids are UUID v4 text.
7. **Errors crossing a boundary are `*kernel/errors.Error`** with a frozen code. Adapters convert driver and transport errors at their own edge.
8. **Secrets never reach a log, an artifact or a plain column.**
9. **No new `.md` files** beyond `CLAUDE.md` and the set in section 10 of the spec.
10. **Bad code is rewritten, not patched.** Commit your own work on `dev` with conventional commits; never amend, rebase, force-push or `--no-verify`. `master` takes a PR from `dev` only when the owner asks.

## Layout and workflow

`cmd/postulator` (bootstrap) · `internal/kernel` (shared) · `internal/domain` (pure) · `internal/application` (use cases) · `internal/adapters` · `internal/runtime` (run engine) · `internal/transport` (wails, agent) · `internal/app` (composition root) · `frontend` (React and Tailwind over the bindings) · `wp-plugin` (PHP).

Dependency rule, enforced by `internal/app/deps_test.go`: domain sees only kernel and stdlib, application sees domain and kernel, only `app` imports `transport`, only `kernel/paging` imports squirrel, and `transport/agent` never reaches `adapters/llm/openai`. The composition root builds by area in `internal/app/build_*.go`.

```
task build                 bin/postulator.exe, builds the frontend and bindings first
task package               the NSIS installer; task e2e:full the whole loop on docker
go test -race ./...        golangci-lint run from $(go env GOPATH)/bin
go run ./cmd/covergate     needs coverage.out from -coverprofile
```

## Footguns

- **A kernel rule**: `log.Logger.Close()` does not call `Sync()`, because syncing a pipe fails on Windows and lumberjack writes unbuffered, so closing the sinks is the whole job. An agent turn recovers its own panic and ends `INTERNAL`; there is no timeout middleware any more.
- **Rules that look like bugs and are not**: a cursor records the sort it was issued for and refuses another `ORDER BY`; `kernel/dto` keeps its own limit constants rather than importing `kernel/paging`, which would drag squirrel into every DTO; a step a run kind owns (`sync_site`, `relink_page`, `revert`, `edit_page`) is a `PerKindStepName` and never a `StepName`, which is what keeps it out of `vocab.ts`, the blank template's recipe and three tool enums at once; `ModelsService.SpendReport` takes no cursor, being an aggregate.
- **Never compare entity names or anchors with `strings.ToLower` or `EqualFold`**: use `graph.Key`, or Go merges or refuses what the store accepts (Café and CAFÉ are two entities; `TestTheGraphKeyRefusesWhatTheStoreRefuses` proves the rule against a real insert). A keyword is found by `keyword.List.Find`, and a list of texts is deduplicated by `graph.Distinct`.
- **Live events are dropped, not buffered** — a progress UI replays `RunsService.ListEvents` — and `frontend/src/generated/events.ts` and `vocab.ts` are generated, committed and checked by a test, while `frontend/bindings/` is generated, gitignored and regenerated only by `task build`, so `npm run typecheck` alone cannot see a bound field a Go change removed: run `task build` before a tag. Those generated files and `go.mod` are pinned to LF, and `frontend/dist/.gitkeep` is committed on purpose because `frontend/assets.go` embeds `all:dist`, so Vite runs with `emptyOutDir: false` and unhashed names or a fresh clone stops building.
- **`TestTheToolSchemasFitTheirCeiling` is a deliberate tripwire**: every tool schema is resent on every round of every turn, so a new tool raises `schemaCeilingBytes` (66,407 for 66,394 bytes and 92 tools since phase 15's proposal `source` and fields) and `schemaCeilingTokens` (14,782 for 14,779 `o200k_base` tokens) in the same commit, and a change that shrinks the schemas lowers them again. `TestTheInstructionsAndTheReplicasBriefFitTheirCeiling` in `application/agent` is its twin for `chat.tmpl` over the replica's captured brief: `instructionsCeilingTokens` 1,932 for the autonomous mode's 1,929. Every enum a tool offers is a vocabulary `vocab.ts` exports, and every field a description. A request struct a tool takes is part of that schema: its `description` tags say what a field takes, its default, its limits and the tool an id comes from, and nothing every field would repeat. The tokenizer behind both lives in `_test.go` files and `cmd/tokenreport` only (`TestTheTokenizerStaysOutOfTheBinary`); `go run ./cmd/tokenreport` is the report, not a gate.
- **OpenAI's Responses API, as the live probe found it**: a structured answer is a strict `json_schema` (every object closed, every property required, an optional one nullable); `minimal` effort, `temperature` at a reasoning effort and `max_output_tokens` under 16 are refused, and the server's default effort is medium even on luna, so an effort is always sent; a `function_call` needs its output in the same input; a reasoning item without its encrypted content is a 404 under `store: false`, so none is kept; an error can arrive inside a stream that answered 200, with no `[DONE]`; a key with no credit validates the request before it refuses, which is how a shape is proven for free. `openaitest` never imports `openai`, as `wptest` never imports `wp`. The chain is tuning → retry → limiter → ledger → recordreplay → openai, so a retried attempt is its own ledger row.
- **PowerShell splits `-coverprofile=coverage.out` into two arguments**, which is why every go and task step of the CI Windows job runs under `shell: bash`.
- **`runs.kind` carries a `CHECK` rebuilt by migrations 0025** (`repair`, `revert`) **and 0073** (`edit`); a tenth kind needs the same rebuild (`NO TRANSACTION`, foreign keys off, explicit `BEGIN`/`COMMIT`) or the insert fails.
- **golangci-lint must be built by the Go release the module targets** and run from `GOPATH/bin`; it runs `errcheck` with `check-blank`, `govet` `enable-all` with non-strict `shadow`, `fieldalignment` off because field order is the JSON order, `gocritic` without `hugeParam`, `misspell` US English ignoring `cancelled`.
- **A product is written in two places, in this order**: the short description (written by `generate_fields`) and the first image, filled only, through `wc/v3` first, then the description through the plugin's raw route against a hash read after that save, because WooCommerce saves the whole post again when a post field changes and kses runs over `post_content` once more, which is also why a product whose save would change its description gets its SEO meta alone. The name, price, stock, SKU, status, slug, categories and attributes are never sent; `wc/v3` replaces the whole attribute list, so only a revert of a run from before 2026-10-20 sends one, whole, through `RestoreAttributes`. A product row keeps the sheet's URL in `planned_path`, which a second import and the export read, and takes no parent from its path.
- **A migration that shipped is undone by a later one, never edited**: the flag model's 0033 and 0034 are undone by 0042 and 0043, and the category records' 0039–0041 by 0044, whose down brings them back.
- **Docker and WordPress quirks**: the WP-CLI image's `www-data` is uid 82 and the WordPress image's is uid 33, so the compose `bootstrap` service runs as `33:33`, needs the `WORDPRESS_DB_*` variables and `WP_ENVIRONMENT_TYPE=local` for application passwords over HTTP; `modified_gmt` has no timezone suffix and core REST filters `modified_after` on the site-local column, which is why the plugin's `/content?since=` exists; `"meta"` arrives as `[]`, not `{}`, for a post type with no registered meta, and `wp.metaBag` takes the array, the object and null.
- **Four docker projects from one compose file**: `task e2e:* STAND=vanilla` is the suites' block-theme stand on 8088 (project `postulator-test-vanilla`, the compose default), `STAND=replica` the replica of the client's first site on 8087 (project `postulator-test-replica`), `STAND=legacy` WordPress 5.7.2 on PHP 7.3 on 8086 for the plugin's contract suite only (`e2e:full` refuses it; `WP_IMAGE`, `WP_CLI_IMAGE` and the bootstrap's per-stand plugin versions make it), and `task sandbox:*` the owner's WordPress on 8089 (project `postulator-e2e`), which comes up bare like a client's site unless `E2E_PLUGIN=1`, is provisioned as a stand only by `task sandbox:provision STAND=` and is wiped only by `sandbox:reset` (Windows reserves 8091–8190 here). A stand's bootstrap writes `docker/e2e/.env.<stand>`, which the suites read through `E2E_STAND` or `POSTULATOR_E2E_ENV`; they force-delete whole sections of the site they run on, so both harnesses refuse 8089 and the sandbox's project, and a stand's term ids start at 100000 because the term-id refusals presume no post shares the id. The plugin is installed from `bin/postulator-companion.zip` (`task plugin:deploy STAND=` reinstalls it) and the replica's mu-plugin is copied, never bind-mounted, because wp-admin's Delete removed the repository's sources through the mount; the replica's theme, plugin and class names live under `docker/e2e/stands/replica` and nowhere in Go or PHP.
- **The companion plugin's post routes answer a content post only** (a public post type other than an attachment), because WordPress numbers a variation, a reusable block, a navigation menu and a template like a page and the raw PUT once wrote into a navigation post. A preview's noindex needs Rank Math's and Yoast's own robots filters, since both replace core's `wp_robots`. `/rendered` filters inside a one-post main query, or a snippet guarded by `is_singular` or `in_the_loop` injects nothing in a REST request. `/content` defaults to the four types a released app asks for. A new capability joins `wp.requiredCapabilities`, the fake's defaults, the PHP `CAPABILITIES`, `openapi.yaml` and three pinned test lists in the same commit. `wpCLI` in the e2e harness costs about six seconds a call.
- **`go test -tags e2e` is the only thing that compiles `internal/e2e` and `internal/adapters/wp/e2e`**, `task lint:e2e` is not optional (it refuses to start beside another golangci-lint; run it alone or by hand with `--allow-parallel-runners`) and `gofmt -l .` is what catches formatting there; `wptest` must never import `wp`, because the fake is a second, independent implementation of the same contract.
- **`VACUUM INTO` cannot write through the adiantum VFS** — it opens the target with no key — so snapshots and restores go through the SQLite online backup API with a plain `file:` URI.
- **A template placeholder is expanded in `templates.ResolveForPage` and nowhere else**; `template.Validate` refuses any `{…}` outside `template.Placeholders()`, so a heading the validator compares is never the placeholder itself. The writer answers a `content.DraftAnswer` with a slot per section and `content.Assemble` puts the brief's headings on; do not compare a body with the raw spec.
- **`run_items.blocked_by` has no foreign key on purpose** — SQLite's `DROP COLUMN` refuses a constrained column, so the down migration would not round-trip — and the release predicate lives twice by design, in `selectRunnableItems` and `selectItemsAwaitingParent`: the blocker's page when there is a blocker, else `pages.parent_page_id`. Change one and the other.
- **A step that returns `TransitionWait` with no artifact and no checkpoint is recorded `ExecStarted`**, never `ExecDone`, or `reuse()` skips it when the item wakes. A step that returns `TransitionPause` keeps its artifacts and is recorded `ExecFailed` with the note, and `sc.Accepted()` is how it learns a person accepted its findings.
- **`Engine.EstimateRun` takes the run and the templates a start is about to assign** (`nil` for none) and resolves each target's template itself; `runtime.Deps.Keys`, `runtime.Deps.Tuning` and `steps.Deps.ImageModel` are required, not optional, and every harness that builds an engine passes a key store and a tuning policy. The writer's ceiling is `writerCeiling(spec, attempts)`, the body's words alone since the short description moved to `generate_fields`, doubled once (`ceilingDoublings`), and the adapter adds the effort's reasoning allowance and clamps it; `llm.WordTokens` (2.2) prices an answer and `steps.tokensPerWord` (3) is the ceiling's, both conservative on purpose, while the input side is measured: `llm.Tokens` and `llm.ReadTokens` read 1.7 tokens a word or 3.7 runes a token, each step's `Price.Overhead` is its measured prompt (the 800 default only for an unmeasured step), a step that `ReadsBody` adds the template's words, nothing scales with the answer, and `Fit` keeps a twentieth of its budget as headroom. `cmd/tokenreport`'s tests hold every measured input within ±25%; a new step or a prompt change that moves them re-measures its overhead.
- **The observation (`application/observe`, driven by `sync_site`) is incremental**: the first walk, one with `full`, every Nth (`settings.observe.fullWalkEvery`, 10) and every walk without the plugin cover the whole site; the others pass the plugin a `since` taken from the site's own stamps (the newest `modified` the previous walk saw, minus that walk's duration and a second, so a server clock behind ours misses nothing), and a page's render is fetched again only when its `modified_gmt` or its body moved past the render's `extracted_at`, or on `renderRescan`. So a page deleted on the site is archived on the next **full** walk only, a render that could not be fetched is `render_unreachable` and is tried again every walk, and `page_identity.observed_at` against the walk's start is how "seen this walk" is known: the checkpoint carries no page ids. A denied field (price, SKU, stock, attributes, a variation's facts) is always agreed (`Fields.Agree`), only a writable field raises `field_changed_on_site`, an open finding re-raised with the same subject touches nothing, and a re-pulled item nothing changed on writes nothing (a field moves only when its hash moves, the page row only when something but its stamps moved).
- **The `h1` field is the H1 a visitor sees, and `pages.h1` is the planned one**: `render.VisibleH1(record, contentH1)` is the one rule (a render with a known `H1Source` wins, else the content's first h1, else none), applied by the content stage with the stored render and by the render stage after each extraction, so no walk flips it. A theme prints the title outside the content root on Blocksy and block themes, which is why the content alone left it empty on every page in 2.5.0. `pages.h1` also mirrors the observed H1 where no plan holds it, and `hasPlan` reads "planned" from the two differing, so only `PageRepo.FollowObservedH1` (where the column still equals the previous observed value) may move it outside `merge`. A render with an unknown `H1Source` whose theme printed an H1 is fetched again on an ordinary walk; `wptest`'s storefront prints the `H1` its plugin reports.
- **Two hashes, never mixed**: `block.BodyHash` is the exact sha256 of the bytes, equal to `wp.ContentHash` and the plugin's `content_hash`, and it is the hash of every body snapshot (`page_bodies.hash`, `Record`, `Observe`, a core or store item's `ContentHash`); `block.Hash` folds CRLF and trims and is a block's identity in `page_blocks_written` only. Hashing a body with the folded one made our own write read as `body_changed_on_site` on every CRLF body and every product without a description.
- **The observation reads the site before its unit of work and writes inside it**: a reader called inside `inUnit` holds the one SQLite writer for a whole round trip, and the observe fakes count such reads (`TestTheObservationReadsTheSiteOutsideItsWriteUnit`). The render stage never visits an archived page or one the walk is about to archive, a failed `GetRendered` is `render_unreachable` like a failed visit, and that finding's subject is the page's path and the status only, so a dismissed one is not reopened by a nonce or an error text.
- **`application/observe` cannot import `adapters/wp`**, so it declares its readers over its own item types and `runtime/steps/observe_readers.go` adapts `*wp.Client`; a change to a `wp` type reaches the observation through that one file. `render.Extract` takes the page's path as `Document` and every href resolves through `Site.ResolveAt`; `Site.Resolve(href)` is `ResolveAt(base, href)`.
- **A parent at the site root is never a WordPress parent on a creation** (`steps.parentOf`, `runs.parentOf`), though `DeriveParent` may name the front page as a flat page's parent by `url` for the tree; a crumb at `/` is dropped like the front page, or vanilla's "Home" crumb would be unresolved on every term page. `publish` sends title, content and status on an update and checks slug, address and parent only on the creation it made, the retry included (`writeRequest.created`).
- **A crumb resolves by its link, then by the redirect the render stage looked up, then by its exact name only when it has no link or a dead one** (`pagemap.DeriveParent`; the method is `pages.parent_method` beside the reason). The lookups (`wp.Client.Resolve`, anonymous HEAD) run in the render stage and live on the crumb in `page_renders.trail`; `derive` stays offline and writes only `PageRepo.UpdateDerived` and `SiteRepo.UpdateObservation`, never a whole row, or an edit made during a walk is lost. A Home-only trail is weak (the other trails, then the WordPress parent, first); the front page is the root, never technical; a page whose own visit lands elsewhere keeps nothing of that page's render; a live link the model lacks never falls to its name.
- **Writers that share one tree commit with `git commit -- <paths>`** and stage nothing ahead of their commit; a plain `git commit` takes the whole index, and R's render commit swept another writer's staged deletions in on 2026-10-18.
- **The read layer has one root and reads, never repeats**: `sitemodel` reads the link audit through `reports`, so `buildAuthoring` builds `reports` before it; a writer's pack loads the site's field rows once with the snapshot and the page's neighbourhood by ids inside one `Store.Read`, while the brief, the tree and the gaps read the whole site once per call; a list built in memory pages through `Keyset.Page`. A conversation's brief is written by `SetBrief` alone, so an `Update` from a copy read before it never clears it, and its bytes stay fixed for the cache: the volatile counts belong to each turn's developer message. `page_blocks_written` is what tells our blocks from the client's: `publish` must record what the site stored, straight after the raw write, or the next run keeps our own article as his text; every block we did not write is his, text or not. Nothing writes a body by re-rendering it whole: a relink goes through `block.Splice`, or every untouched block changes its bytes and its hash.
- **A test harness waits until its test's deadline, never a fixed span** (`waitDeadline` in the runtime, steps and sync harnesses): under `-race -cpu 1` a three-page sweep runs past a minute, so a fixed 20 s failed it; a `-count` loop needs `-timeout`, or its waits give up near the binary's own ten minutes.
- **`findings.ResolveRequest.By` and `ResolveManyRequest.By` are `json:"-"`**: a bound call is the person's, and only the agent's tool sets `agent`. A resolution writes through `PageRepo`, because `pages.Service` publishes `pages.changed` after its own unit, which inside the resolution's is before the commit; a card's acceptance and a row's mapping still go through their services and are never bulk.
- **A store category with a hub twin is never a map row**: the hub carries it (`MapNode.Twin`), its id answers the hub's node and its children are the hub's, so code that walks the map asks `contextpack.Map`, not the index. A body's state counts a block the parser marks dynamic (a textless figure) as nobody's text.
- **Run `e2e:full` on both stands at every stage's close**: 4.1's URL-less-row ruling turned `TestTheClientLoopFromTheSamples` red, and no stand ran the whole suite until 4.3b. `task build` runs `go mod tidy`, and the samples build (`samples/build`, `npm run build`) rewrites every workbook's bytes even when its sheets did not change: restore those before committing.
- **`page_map` (0074) is the Site map, materialized**, kept fresh by triggers on `pages`, `page_fields` and `page_types` that bump `page_map_sites.generation`; a migration that rebuilds one of those tables must recreate the triggers, or the map goes stale silently. `internal/app/scale` proves the reads flat at 2,000 and 5,000 pages and skips under `-race` (`//go:build !race`), so the gate runs it without race.
- **A version lives in seven places**: `build/config.yml`, `build/windows/info.json`, `build/windows/nsis/wails_tools.nsh` (the installer's version: no `makensis` call passes one, which is how every installer from 2.0.0 to 2.4.0 registered as 2.0.0), `frontend/package.json` and its lock, and the `-dev` defaults of `Taskfile.yml` and `internal/app/version.go`; the tag's workflow passes `VERSION` to the build and the package.
- **The UI harness walk proves layout with `fits`** (`frontend/scripts/shot.mjs`): a shot fails when its element, or anything scrolling inside it, holds content wider than itself. Routes in `routes.json` share one window, so a route that needs the dock open sits after one that opens it.

## Standing rulings

Dated in full in [`docs/DECISIONS.md`](docs/DECISIONS.md); these, as they stand at 2.5.0, are the ones that change how you write code here.

- **Kernel and transport.** UUIDs come from the standard library and `kernel/id.Valid` checks v4; `paging.Cut` is a `Keyset` method; `errors.Wrap` returns `error`; the kernel exports nothing only its own test calls. A Wails service declares the use case it consumes, resolves it per call through a `Source[T]` (which answers `Locked` while the core is closed), returns `wails.Convert(err)` and sets its marshaller with `NewServiceWithOptions`; the Go registry renders the event typings; `SettingsService` alone accepts a credential; `app.Config.Provider` is the end-to-end harness's seam.
- **WordPress and the plugin.** `adapters/wp` is the one place page numbers are legal; `wp.ContentHash` is `hex(sha256(raw))`; `wp-plugin/openapi.yaml` changes on both sides at once; the plugin targets PHP 7.2 and WordPress 5.7 (2026-10-24, amending 10-12: no typed properties, arrow functions, `??=`, spread, `match`, `?->`, named arguments, union types, `str_contains`; `tests/functions.php` fails on any function newer than the PHP running it or missing from `testdata/wordpress.json` with its `@since`, and on a header below the list's newest), its lint and tests run on 7.2, 7.4 and 8.5 under `E_ALL`, it never removes a kses filter, `wp_slash`es every write, and its version moves with its contract (1.5.2 is bundled, `wp.PluginMinimum` 1.5.1 is required).
- **The domain and the tools.** The domain imports only `robfig/cron/v3` and `x/net/html` beyond the standard library and the kernel. A tool takes its own argument structs, masks a call's arguments before a ledger, an event, a summary or a history, takes its risk from its arguments (`Tool.RiskOf`), and refuses the call when it cannot build its summary.
- **Models.** OpenAI only, through our Responses client in `adapters/llm/openai`; a structured answer is one strict call; effort and tier belong to a role (`llm.effort.*`, `llm.tier.*`), never a catalog row; every attempt is a ledger row and a call's purpose is derived, never stored; a built-in price is never 0; a single call stays out of the prompt cache. Tokens are counted only in tests and `cmd/tokenreport`.
- **One model of the site** (2026-10-17 to 19). Every page of every post type is identity, fields, a body of blocks, its render's regions, typed links, JSON-LD, a page type and a derived hierarchy with a reason, filled by four providers behind the field registry and read by the writer, the agent and every screen through `application/sitemodel` alone; the link audit is read, never repeated. The parent comes from a BreadcrumbList, an ARIA breadcrumb, the WordPress parent, then the URL, a crumb resolving by link, redirect, then name; the derived parent wins unless a person pins the workbook's. No theme name, CSS class or site path lives in Go or PHP, and nothing a visitor receives names the program.
- **Nothing structural is written to an existing page**: slug, status, parent, prices, stock, SKU, every taxonomy, a variation's attributes; a planned page's one creation call may set status, parent and slug, never at the site root. Products are the client's, edited where they stand within the product type's field scope; no WordPress or WooCommerce category is written or kept as a record of its own.
- **Ours is what the site stored** (stage 3). `page_blocks_written`, the publish result's `blocks`, the field bases and the SEO record come from the site's answer; every block we did not write is the client's, kept byte for byte unless a run confirmed rewriting his text; nothing re-renders a body whole; every write goes under the hash read and keeps what it replaced, so a revert works per field and per block and hands back what the client changed since.
- **Every write is a run.** Fields go through `application/edit`, `publish` makes one write per execution, a draft run's writes wait for a person's review (whole or field by field, never by the agent), and every agent write to a page is a one-item `edit` run (`runs.StartEdit`) that waits for the person in either mode; a run scoped to fields keeps only the steps they need.
- **The workbook reconciles through findings** (stage 4). Every row finds its page through `pagemap.MatchRow` (mapped, URL, slug, entity, title, H1, SKU); a URL-less row no page answers plans one under its sheet parent, an entity-only row plans none; only a Root column makes groups, and the other level columns are the row's expected trail. A tie is `row_ambiguous`, settled by a pick in the preview or by `map_to_page`. A finding lives once per subject and stays settled while its subject stands; each option changes the model or answers a run's request, never writes to the site; `findings.Explain` is the one sentence of what an option does, and `ResolveMany` takes only `finding.BulkOptions()`, at most 1,000 in one unit (more would hold SQLite's writer past its 5 s busy timeout), so the inbox sends batches and says what a refused one left unsettled.
- **One tree.** `contextpack.Map` (derived parent, a store category folded into the hub of its name) is what the Site map, the findings' subtree and the run start's picker read, through `page_map` and `sitemodel.Refresh`, never recomputed per request; `Pages.Tree` stays only for the Overview's and the Reports' whole-tree reads.
- **Runs and links.** A run kind that owns its steps hands them out and no template overrides them; an import never plans `/`; a draft is assembled from the brief and a missing section is tried again, never failed; validation grades and a person accepts through `Engine.Accept`; a child waits behind its parent (`blocked_by`); an owed link is placed or said, never dropped; one `pagemap.Site` answers where an href points and `content.Subject` which page is self.
- **Words and names.** Keywords are one `keyword.List` read through `pagemap.Keywords` and parsed only by `keyword.Parse`; an entity's name is unique under its parent, and a shared one reaches a prompt or an anchor only through `graph.Labels`.
- **The writer.** Its pack is fitted to `llm.inputBudget.<role>` and refused in preflight when too small; `Sanitize` keeps only the links the policy and the plan allow and strips classes, ids, styles and data attributes; nothing that re-saves a post goes over a page that is not save-stable; the canonical is a person's switch, written once on a live creation; an existing page's status is never written. A card the agent proposes is an `entity_card_proposed` finding, written only when accepted and refused when the card moved since.
- **Pages without an entity** (phase 15). A writable page no entity carries is a `page_without_entity` finding (derive raises and clears it; every writer that maps a page clears it as `model`, so an unmap opens it again); its `propose_entity` answers the site preview (`PreviewFromPages{source: site}`, `contextpack.Map.EntityProposals`, no model call), and a person's acceptance writes each entity under its parent with the edge approved, a clash skipped, never the batch refused. The steps still refuse a page with no entity; the graph stays the source of every link.
- **The agent.** Its chat is bound to the selected site (`/s/:siteId/agent`, the same conversation the dock holds; `/agent` only for site-less chats). Its brief is kept per conversation, `pages_get` (`sitemodel.Page`) is its one page view and `sites_explore` its query; resolving a finding and starting a run follow the conversation's mode, a write to a page and an entity proposal's write (`graph_apply_proposals`, `graph_propose_from_pages`) wait for the person in either.

## Product guardrail

Postulator builds one structured model of a client's site (its pages, fields, hierarchy, products and links, reconciled with his workbooks and his entity graph) and edits the site's content through it, so every page is written with the full picture and linked as the graph says. Reject features that do not serve that loop.
